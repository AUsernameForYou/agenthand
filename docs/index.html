agenthand

agenthand turns any photo into a working asset, for AI agents that help people sell.

The seller never opens agenthand. Their agent calls it, the way a hand is called: quietly, in the middle of other work.

Get it on GitHub The Fidelity Lock

01What it does

Three tools, one asset

A seller hands their agent a photo from the kitchen table: bad light, busy background, the item half in shadow. Three calls later it is a listing.

STEP 1

identify

Reads the photo and plans the job. What the item is, what a buyer would call it, the words for the listing, and exactly which pixels are the product.

STEP 2

cut_out

Lifts the product out of its photo, pixel for pixel, and hands back a clean cut-out on transparency. Nothing is redrawn; the real product is the layer.

STEP 3

draw

Stages the scene around it: a regal reading room, a clean studio sweep, a table set for the season. The setting is generated. The product is not.

02Fidelity Lock

The product is never regenerated

Generated staging has a trust problem: buyers cannot tell whether the item in the pretty picture is the item that ships. Fidelity Lock answers it with proof instead of promises.

The image model paints only the empty scene. The real product layer is placed into it by plain, deterministic code, untouched. Then agenthand counts: across the whole product, the number of changed pixels is zero, and it prints the receipt to show it.

  1. The product is cut out of the seller's photo and stored untouched, with hashes of the source, the layer, and the mask.
  2. The image model generates the background scene only. It never receives the product's pixels.
  3. Deterministic code composites the stored layer onto the scene. Before anything moves, the stored hashes are verified.
  4. Every result ships with its receipt: the hashes, what was transformed, the changed-pixel count, and the cost of the calls that made it.

The claim is precise on purpose: the stored product layer reached the final image unchanged. Edge pixels that blend with the scene are counted separately in the receipt, never hidden inside the zero.

03The scale card

A known size, laid in the photo

The agenthand scale card is a printed, laminated card that goes in the photo, next to the thing being sold. Its face is the agenthand mark itself: the robot hand, the three arcs, and the black corner brackets that frame them. The only added furniture is a set of white ticks cut into those bracket arms at exact, known positions. Nothing else is printed on it: no numbers, no rulers, no labels. The geometry the pipeline needs lives in a layout profile on the machine side, where every bracket corner and tick sits at known coordinates. It comes in two sizes: 5×7 in beside a product, and a 4×6 in postcard for scenes, printed three to a letter sheet and cut down.

[ roadmap ]

A known shape in the frame is a foothold. With one, agenthand could be built to read the bracket corners and ticks against their known geometry, fit the photo's perspective, and estimate the item's size, its distance from the camera, an area of floor or wall, and a rough volume for simple shapes. Estimates would come back as approximations, tilde and range included, never dressed up as exact figures. More cards placed at more depths would tighten the estimate. Paced or measured distances between cards would tighten it again. The design is locked and the print files are ready; measuring is not built.

04Use it

An MCP server, over stdio today

agenthand speaks the Model Context Protocol. Run it locally and point any MCP client at it; a hosted endpoint comes later.

git clone https://github.com/AUsernameForYou/agenthand
cd agenthand
python3.12 -m venv .venv
.venv/bin/pip install -e ".[dev]"
.venv/bin/agenthand          # stdio transport

Then register it with your MCP client:

{
  "mcpServers": {
    "agenthand": {
      "command": "/path/to/agenthand/.venv/bin/agenthand",
      "env": { "META_API_KEY": "…" }
    }
  }
}

Images travel as asset:// handles, not bytes, so tools chain: identify plans, cut_out returns a handle, draw consumes it. Every billable call passes one spend cap with reserve-then-settle receipts, and the server refuses to spend when the ledger cannot be trusted.
